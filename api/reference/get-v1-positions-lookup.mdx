## Authorization

`read`, with exact scope checked against the looked-up position.

## Behavior

Resolve an authorized canonical position UUID without inferring account or venue from the UUID. The response keeps the standard Position publication envelope. An inaccessible position can be reported as absent.

## Request example

```http
GET /v1/positions/lookup?id=11111111-1111-4111-8111-111111111111
Authorization: Bearer YOUR_API_KEY_FROM_PRIVATE_STORAGE
```

All IDs and dates are illustrative. URL-encode opaque query values and supply each allowed key once. Optional filters and their types appear in the generated schema below.
