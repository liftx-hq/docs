## Authorization

`read` for the exact active position.

## Behavior

Returns the current active Position publication with revision, slots and physical order identities. It is not a ready-to-submit PositionRequest. Construct a complete intended request, preserve current rows and send its revision as expected_revision on a new MODIFY command. A stale or absent active runtime position is not a safe basis for modification.

## Request example

```http
GET /v1/positions/get-for-modification?id=11111111-1111-4111-8111-111111111111&exchange_link_id=17&instrument_id=COPY_EXACT_CATALOG_ID
Authorization: Bearer YOUR_API_KEY_FROM_PRIVATE_STORAGE
```

All IDs and dates are illustrative. URL-encode opaque query values and supply each allowed key once. Optional filters and their types appear in the generated schema below.
